# Tema 1. Instalación y actualización de aplicaciones ofimáticas

A diario utilizamos programas que nos permiten escribir documentos, realizar cálculos, crear presentaciones, gestionar información, comunicarnos o trabajar con imágenes y otros contenidos.

Muchas de estas aplicaciones forman parte de lo que conocemos como **software ofimático**.

Cuando pensamos en ofimática, probablemente lo primero que nos viene a la cabeza es un procesador de textos como Word o Writer, una hoja de cálculo como Excel o Calc o un programa de presentaciones como PowerPoint o Impress.

Sin embargo, la ofimática es mucho más amplia.

Una empresa puede utilizar aplicaciones para:

* Redactar contratos.
* Elaborar presupuestos.
* Crear facturas.
* Llevar la contabilidad.
* Gestionar inventarios.
* Crear presentaciones.
* Organizar calendarios.
* Gestionar el correo electrónico.
* Crear bases de datos.
* Editar imágenes.
* Editar vídeo.
* Compartir documentos.
* Trabajar simultáneamente varias personas sobre un mismo archivo.
* Gestionar información almacenada en la nube.

En este tema aprenderemos algo que desde el punto de vista de un técnico de Sistemas Microinformáticos y Redes es especialmente importante:

> **No basta con saber utilizar una aplicación. También debemos saber identificar qué aplicación necesita un usuario, comprobar si su equipo puede ejecutarla, instalarla correctamente, configurarla, actualizarla y solucionar los problemas que puedan aparecer.**

Esta es precisamente una de las funciones profesionales relacionadas con el módulo de **Aplicaciones ofimáticas (0223)**.

---

## 2. ¿Qué es la ofimática?

La palabra **ofimática** procede de la combinación de los términos:

* **ofi**cina
* **informática**

Podemos definir la ofimática como:

> **El conjunto de técnicas, herramientas y aplicaciones informáticas destinadas a facilitar y automatizar las tareas habituales de una oficina o de un entorno profesional.**

Estas tareas pueden estar relacionadas con la creación, modificación, almacenamiento, procesamiento, comunicación y distribución de información.

Por ejemplo, imaginemos una pequeña empresa.

En ella puede ser necesario:

1. Crear documentos de texto.
2. Realizar presupuestos.
3. Mantener una lista de clientes.
4. Crear presentaciones comerciales.
5. Gestionar el correo electrónico.
6. Organizar reuniones.
7. Crear informes.
8. Realizar cálculos.
9. Compartir documentación.
10. Archivar información.

Todas estas tareas pueden realizarse mediante herramientas informáticas.

Por tanto, la ofimática no consiste simplemente en **"usar Word"**.

Es un conjunto de herramientas destinadas a resolver necesidades de información y comunicación dentro de una organización.

---

## 3. Aplicaciones ofimáticas

Una **aplicación ofimática** es un programa informático diseñado para realizar una o varias tareas relacionadas con la gestión de información en un entorno personal, educativo o profesional.

Algunos ejemplos son:

| Tipo de aplicación         | Ejemplos de tareas                        |
| -------------------------- | ----------------------------------------- |
| Procesador de textos       | Crear cartas, informes, contratos         |
| Hoja de cálculo            | Cálculos, presupuestos, estadísticas      |
| Presentaciones             | Exposiciones y presentaciones comerciales |
| Base de datos              | Gestión de clientes, productos o pedidos  |
| Correo electrónico         | Comunicación profesional                  |
| Calendario                 | Organización de reuniones y eventos       |
| Editor de imágenes         | Tratamiento de fotografías y gráficos     |
| Editor de vídeo            | Creación y edición de vídeos              |
| Gestor de documentos       | Almacenamiento y organización documental  |
| Herramientas colaborativas | Trabajo simultáneo sobre documentos       |

Una característica importante es que **una misma aplicación puede realizar varias funciones**.

Por ejemplo, una suite ofimática puede incluir:

* Procesador de textos.
* Hoja de cálculo.
* Programa de presentaciones.
* Herramienta para crear diagramas.
* Gestor de bases de datos.

---

## 4. Suites ofimáticas

Una **suite ofimática** es un conjunto de aplicaciones relacionadas entre sí que se distribuyen como un paquete.

La principal ventaja de una suite es que sus aplicaciones suelen compartir:

* Interfaz.
* Configuración.
* Formatos.
* Recursos.
* Sistema de instalación.
* Integración entre aplicaciones.

Por ejemplo, una suite puede permitir crear una tabla en una hoja de cálculo y posteriormente insertarla en un documento de texto.

## 4.1. Ejemplos de suites ofimáticas

Entre las suites ofimáticas conocidas encontramos:

* Microsoft 365.
* LibreOffice.
* ONLYOFFICE.
* Google Workspace.
* Apple iWork.

No todas funcionan exactamente de la misma manera.

Algunas están diseñadas principalmente para trabajar de forma local y otras están especialmente orientadas al trabajo en la nube.

---

## 5. Aplicaciones ofimáticas locales

Una aplicación **local** es aquella que se instala y ejecuta en el ordenador del usuario.

Por ejemplo:

```text
Ordenador
   │
   ├── Sistema operativo
   │
   └── Aplicación ofimática
          │
          ├── Procesador de textos
          ├── Hoja de cálculo
          └── Presentaciones
```

En este modelo, los archivos pueden almacenarse en:

* Disco duro.
* SSD.
* Memoria USB.
* Disco externo.
* Servidor de archivos.
* Carpeta de red.

### Ventajas

* Puede funcionar sin conexión a Internet.
* El usuario tiene un mayor control sobre el software instalado.
* Puede trabajar con archivos almacenados localmente.
* Puede ofrecer más funcionalidades que determinadas versiones web.

### Inconvenientes

* Hay que instalar el programa.
* Hay que mantenerlo actualizado.
* Hay que gestionar las licencias.
* Puede requerir determinados recursos de hardware.
* El usuario debe encargarse de realizar copias de seguridad si los archivos se almacenan localmente.

---

## 6. Aplicaciones ofimáticas en la nube

En los últimos años ha aumentado considerablemente el uso de aplicaciones que funcionan mediante Internet.

En este modelo, una parte importante del procesamiento y del almacenamiento puede realizarse en servidores externos.

El usuario accede normalmente mediante:

* Navegador web.
* Aplicación específica.
* Aplicación móvil.

Por ejemplo:

```text
Usuario
   │
   │ Internet
   ▼
Servidor / plataforma cloud
   │
   ├── Aplicación
   ├── Documentos
   └── Datos
```

Una de las principales ventajas es que el usuario puede acceder a sus documentos desde diferentes dispositivos.

Por ejemplo:

> Un alumno empieza un documento en el ordenador del aula, continúa trabajando desde su ordenador de casa y posteriormente lo consulta desde un teléfono móvil.

---

## 7. Software local frente a software en la nube

| Característica                   | Aplicación local            | Aplicación en la nube              |
| -------------------------------- | --------------------------- | ---------------------------------- |
| Instalación                      | Normalmente necesaria       | Puede no ser necesaria             |
| Internet                         | Puede no ser necesario      | Generalmente necesario             |
| Almacenamiento                   | Local o elegido por usuario | Frecuentemente remoto              |
| Actualizaciones                  | Deben gestionarse           | Suelen gestionarse automáticamente |
| Acceso desde varios dispositivos | Depende de configuración    | Habitualmente sencillo             |
| Trabajo colaborativo             | Puede existir               | Habitualmente muy integrado        |
| Dependencia del proveedor        | Menor                       | Mayor                              |
| Control del sistema              | Mayor                       | Menor                              |
| Disponibilidad                   | Depende del equipo          | Depende del servicio y conexión    |

Ninguna de las dos opciones es automáticamente mejor.

La elección depende de las necesidades del entorno.

## 10. Aplicaciones de presentaciones

## 11. Bases de datos ofimáticas

Una base de datos permite almacenar y organizar grandes cantidades de información estructurada.

Por ejemplo, una empresa podría almacenar:

```text
CLIENTES

ID | Nombre | Teléfono | Email
----------------------------------
1  | Ana    | ...      | ...

3  | Marta  | ...      | ...
```

Una base de datos permite posteriormente realizar consultas.

Por ejemplo:

> Mostrar todos los clientes de Alicante.

O:

> Mostrar todos los clientes que realizaron una compra durante el último mes.

Permiten:

En un entorno empresarial pueden resultar fundamentales para la organización diaria.

## 13. Herramientas de colaboración

Las aplicaciones modernas permiten que varias personas trabajen sobre un mismo documento.

Por ejemplo:

```text
                  Documento
                     │
        ┌────────────┼────────────┐
        │            │            │
      Ana          Luis         Marta

        └────────────┼────────────┘
```

Esto permite trabajar de forma colaborativa sin tener que enviar continuamente diferentes versiones del archivo.

## 14. ¿Cómo elegir una aplicación ofimática?

Uno de los errores más habituales es pensar:

> "La aplicación más conocida es siempre la mejor."

No necesariamente.

Un técnico debe analizar las necesidades antes de elegir una solución.

Algunos factores importantes son:

### 14.1. Funcionalidad

¿Qué necesita hacer el usuario?

No tiene sentido instalar una aplicación extremadamente compleja si el usuario solamente necesita crear documentos sencillos.

---

### 14.2. Compatibilidad

Debemos comprobar:

* Sistema operativo.
* Arquitectura.
* Hardware.
* Formatos de archivo.
* Otras aplicaciones utilizadas.

---

### 14.3. Precio

Hay soluciones:

* Gratuitas.
* De pago único.
* Basadas en suscripción.
* Financiadas mediante otros modelos.

El precio debe analizarse dentro del contexto de la organización.

---

### 14.4. Licencia

Es fundamental conocer qué permite hacer la licencia.

No debemos confundir:

> **gratuito**

con:

> **libre**

Son conceptos diferentes.

---

### 14.5. Privacidad

Debemos analizar dónde se almacenan los datos y quién puede acceder a ellos.

Esto es especialmente importante en empresas, centros educativos y administraciones públicas.

---

### 14.6. Soporte

Una organización puede necesitar:

* Soporte técnico.
* Documentación.
* Actualizaciones.
* Asistencia del fabricante.
* Comunidad de usuarios.

## 15. Licencias de software

Una licencia de software establece las condiciones bajo las cuales podemos utilizar un programa.

Cuando instalamos software no significa necesariamente que pasemos a ser propietarios del programa.

Normalmente estamos adquiriendo o aceptando un **derecho de uso** sujeto a determinadas condiciones.

---

## 16. Software propietario

El software propietario es aquel cuyo control sobre el código y las condiciones de distribución pertenece a una persona, empresa u organización.

Normalmente el usuario:

* Puede utilizar el programa según la licencia.
* No dispone necesariamente del código fuente.
* No puede modificarlo libremente.
* No puede redistribuirlo libremente.

Esto no significa necesariamente que sea software de pago.

Puede existir software propietario gratuito.

---

## 17. Software libre

El concepto de **software libre** hace referencia a las libertades que tiene el usuario sobre el programa.

Entre ellas se encuentran las relacionadas con:

* Ejecutar el programa.
* Estudiar su funcionamiento.
* Modificarlo.
* Redistribuir copias.
* Distribuir versiones modificadas.

Por tanto:

> **Software libre no significa simplemente "software gratis".**

Una aplicación puede ser libre y comercializarse.

---

## 18. Código abierto

El concepto **open source** o código abierto pone especial énfasis en la disponibilidad del código fuente y en las condiciones que permiten estudiarlo, modificarlo y redistribuirlo según su licencia.

Software libre y open source están estrechamente relacionados, aunque son conceptos que proceden de enfoques diferentes.

Para un técnico es importante comprender que:

> **Lo importante no es únicamente si podemos descargar un programa gratuitamente, sino qué derechos nos concede su licencia.**

---

## 19. Freeware, shareware y software de pago

Podemos encontrarnos diferentes modelos de distribución.

### Freeware

Software que puede utilizarse gratuitamente bajo determinadas condiciones.

### Shareware

Software que puede ofrecerse gratuitamente durante un periodo o con determinadas limitaciones.

### Software comercial

Software que requiere algún tipo de pago para utilizarlo o acceder a determinadas funcionalidades.

### Suscripción

El usuario paga periódicamente por mantener el acceso al software o servicio.

Por ejemplo:

```text
Pago único
     ↓
Licencia permanente
```

frente a:

```text
Pago mensual/anual
        ↓
Suscripción
        ↓
Acceso mientras se mantiene el servicio
```

Las condiciones exactas dependen de cada licencia.

## 21. Requisitos del sistema

Los fabricantes suelen indicar unos requisitos mínimos o recomendados.

Entre ellos podemos encontrar:

* Sistema operativo.
* Procesador.
* Memoria RAM.
* Espacio disponible.
* Tarjeta gráfica.
* Resolución de pantalla.
* Conexión a Internet.
* Arquitectura del sistema.

---

## 22. Requisitos mínimos y recomendados

No debemos confundir ambos conceptos.

### Requisitos mínimos

Son las condiciones necesarias para que el programa pueda funcionar.

Por ejemplo:

```text
RAM: 4 GB
Almacenamiento: 5 GB
Sistema operativo: X
```

### Requisitos recomendados

Son unas condiciones superiores que permiten trabajar con mayor comodidad.

Por ejemplo:

```text
RAM: 8 GB
Almacenamiento: 10 GB
SSD
```

Que un ordenador cumpla los requisitos mínimos **no significa que vaya a ofrecer un buen rendimiento**.

---

## 23. Compatibilidad

Antes de instalar debemos comprobar si existe compatibilidad entre:

* Hardware.
* Sistema operativo.
* Aplicación.
* Arquitectura.
* Otros programas.
* Controladores.
* Formatos.

Por ejemplo, una aplicación puede funcionar correctamente en Windows pero no disponer de una versión equivalente para Linux.

También podemos encontrar aplicaciones:

* De 32 bits.
* De 64 bits.
* Multiplataforma.

---

## 24. Arquitectura de 32 y 64 bits

La arquitectura del sistema operativo puede influir en la compatibilidad del software.

Actualmente los sistemas de 64 bits son predominantes en ordenadores personales.

Sin embargo, todavía podemos encontrarnos con aplicaciones antiguas diseñadas para arquitecturas anteriores.

Antes de instalar software debemos comprobar:

> ¿Qué versión corresponde a nuestro sistema?

---

## 25. Fuentes de instalación

Una aplicación puede distribuirse de diferentes formas.

Por ejemplo:

* Página oficial del fabricante.
* Tienda oficial del sistema operativo.
* Repositorio de software.
* Medio físico.
* Servidor interno de la organización.
* Sistema de despliegue centralizado.

Como norma general:

> **Debemos obtener el software desde una fuente fiable y legítima.**

En un entorno profesional no deberíamos instalar aplicaciones obtenidas de páginas desconocidas simplemente porque aparezcan en un buscador.

---

## 26. El instalador

El **instalador** es el programa o mecanismo encargado de realizar la instalación.

Durante el proceso puede:

* Copiar archivos.
* Crear carpetas.
* Crear accesos directos.
* Registrar componentes.
* Crear entradas de configuración.
* Añadir extensiones.
* Configurar servicios.
* Crear asociaciones de archivos.
* Registrar información necesaria para desinstalar el programa.

Por eso instalar una aplicación no consiste simplemente en copiar un archivo `.exe`.

---

## 27. Fases de una instalación

Una instalación profesional puede dividirse en varias fases.

## Fase 1. Análisis de necesidades

Debemos determinar:

* Qué necesita el usuario.
* Qué aplicación se utilizará.
* Qué funcionalidades son necesarias.

---

## Fase 2. Comprobación del sistema

Verificamos:

* Sistema operativo.
* RAM.
* CPU.
* Espacio disponible.
* Arquitectura.
* Conectividad.
* Software existente.

---

## Fase 3. Comprobación de licencia

Debemos comprobar:

* Tipo de licencia.
* Número de usuarios.
* Número de dispositivos.
* Duración.
* Condiciones de utilización.

---

## Fase 4. Preparación

Antes de instalar podemos:

* Cerrar aplicaciones.
* Realizar una copia de seguridad.
* Crear un punto de restauración.
* Comprobar espacio disponible.
* Descargar el instalador.
* Verificar la versión.

---

## Fase 5. Instalación

Se ejecuta el instalador.

Durante este proceso pueden aparecer diferentes opciones.

---

## Fase 6. Configuración

Después de instalar debemos adaptar el programa a las necesidades del usuario.

Por ejemplo:

* Idioma.
* Formato predeterminado.
* Carpeta de documentos.
* Impresora.
* Cuenta de usuario.
* Extensiones.
* Integraciones.

---

## Fase 7. Pruebas

No debemos asumir que una instalación ha funcionado simplemente porque el instalador haya terminado.

Debemos probar la aplicación.

Por ejemplo:

1. Abrirla.
2. Crear un documento.
3. Guardarlo.
4. Volver a abrirlo.
5. Comprobar una función importante.
6. Comprobar la impresión o exportación.

---

## Fase 8. Actualización

Finalmente debemos comprobar si existe una versión actualizada o parches disponibles.

---

## Fase 9. Documentación

El técnico debe dejar constancia de:

* Aplicación instalada.
* Versión.
* Fecha.
* Equipo.
* Usuario.
* Configuración.
* Incidencias.
* Soluciones aplicadas.

---

## 28. Instalación típica frente a instalación personalizada

Muchos instaladores ofrecen dos opciones.

### Instalación típica

Instala una configuración predeterminada.

Ventajas:

* Rápida.
* Sencilla.
* Adecuada para usuarios sin conocimientos técnicos.

Inconvenientes:

* Puede instalar componentes innecesarios.
* Ofrece menos control.

---

### Instalación personalizada

Permite seleccionar componentes y opciones.

Por ejemplo:

```text
Aplicación principal       ✓
Diccionario español        ✓
Diccionario inglés         ✗
Extensiones                ✓
Herramientas adicionales   ✗
Accesos directos           ✓
```

En un entorno profesional puede ser preferible utilizar la instalación personalizada cuando necesitamos controlar exactamente qué componentes se instalan.

---

## 29. Componentes de una aplicación

Una aplicación puede estar formada por diferentes componentes.

Por ejemplo:

```text
Suite ofimática
│
├── Procesador de textos
├── Hoja de cálculo
├── Presentaciones
├── Diccionarios
├── Correctores
├── Plantillas
├── Extensiones
└── Herramientas adicionales
```

No siempre es necesario instalar todos.

Por eso algunas aplicaciones permiten realizar instalaciones parciales.

Esto está directamente relacionado con uno de los criterios del RA1: **añadir o eliminar componentes de la instalación**. ([BOE][1])

## 30. Configuración de una aplicación

Después de instalar una aplicación debemos configurarla.

La configuración dependerá del programa.

Algunas opciones habituales son:

### Idioma

```text
Idioma de interfaz: Español
Idioma de corrección: Español
```

### Ubicación de documentos

```text
C:\Usuarios\Alumno\Documentos
```

### Guardado automático

Podemos establecer:

* Frecuencia de guardado.
* Ubicación.
* Copias de recuperación.

### Formatos predeterminados

Podemos seleccionar qué formato utilizar al guardar documentos.

---

## 31. Asociaciones de archivos

Una asociación de archivos indica qué aplicación debe abrir determinado tipo de archivo.

Por ejemplo:

```text
.odt → Writer
.xlsx → Excel
.pdf → visor PDF
```

Cuando hacemos doble clic sobre un archivo, el sistema operativo consulta estas asociaciones.

Un técnico puede necesitar modificarlas.

---

## 32. Instalación y permisos

Al instalar software podemos necesitar permisos administrativos.

Esto depende de:

* Sistema operativo.
* Tipo de instalación.
* Ubicación.
* Políticas de seguridad.

En una empresa no debería utilizarse sistemáticamente una cuenta con permisos administrativos para todas las tareas.

Una buena política consiste en aplicar:

> **El principio de mínimo privilegio.**

Es decir, cada usuario debería disponer únicamente de los permisos necesarios para realizar su trabajo.

---

## 33. Actualizaciones

Una aplicación informática no queda "terminada" cuando se instala.

Los desarrolladores publican actualizaciones por diferentes motivos:

* Corrección de errores.
* Mejoras de rendimiento.
* Nuevas funcionalidades.
* Compatibilidad.
* Correcciones de seguridad.

Por tanto:

> **Mantener actualizado el software es parte del mantenimiento del sistema.**

---

## 34. Tipos de actualizaciones

Podemos encontrar diferentes tipos.

### Actualización de mantenimiento

Corrige errores o pequeños problemas.

### Actualización de seguridad

Soluciona vulnerabilidades.

### Actualización funcional

Añade nuevas funcionalidades.

### Nueva versión

Puede introducir cambios importantes en la aplicación.

Por ejemplo:

```text
Versión 1.0
   ↓
1.1 → correcciones
   ↓
1.2 → mejoras
   ↓
2.0 → nueva versión
```

La nomenclatura concreta depende del desarrollador.

---

## 35. Actualización automática y manual

## Automática

El programa comprueba y descarga las actualizaciones automáticamente.

### Ventajas

* Menos trabajo para el usuario.
* Reduce el riesgo de olvidar actualizaciones.

### Inconvenientes

* Menor control.
* Puede producir cambios inesperados.
* Puede consumir ancho de banda.
* En una empresa puede ser necesario probar antes las actualizaciones.

---

## Manual

El administrador decide cuándo realizar la actualización.

Puede ser recomendable en determinados entornos profesionales donde las aplicaciones deben probarse antes de desplegarse.

---

## 36. Actualizaciones en una organización

Imaginemos una empresa con 100 ordenadores.

No sería necesariamente buena idea instalar inmediatamente una actualización en los 100 equipos.

Podríamos utilizar una estrategia como:

```text
Actualización disponible
          ↓
Pruebas
          ↓
Equipo piloto
          ↓
Comprobación
          ↓
Despliegue progresivo
          ↓
Todos los equipos
```

Esto reduce el riesgo de que una actualización provoque un problema generalizado.

---

## 37. Gestión de versiones

Un técnico debe saber qué versión está instalada.

Por ejemplo:

```text
Aplicación: LibreOffice
Versión: X.Y
Arquitectura: 64 bits
Sistema operativo: Windows
Fecha de instalación: XX/XX/XXXX
```

Esta información resulta especialmente útil cuando aparece una incidencia.

Por ejemplo:

> "La aplicación funciona correctamente en la versión 1.5 pero falla después de actualizar a la 1.6."

Sin conocer las versiones sería mucho más difícil investigar el problema.

---

## 38. Documentación de instalaciones

La documentación es una parte importante del trabajo técnico.

Una instalación profesional podría registrarse mediante una ficha:

| Campo       | Información           |
| ----------- | --------------------- |
| Equipo      | PC-AULA-01            |
| Usuario     | alumno01              |
| Aplicación  | Suite ofimática       |
| Versión     | X.Y                   |
| Fecha       | 15/09/2026            |
| Licencia    | Tipo de licencia      |
| Instalación | Personalizada         |
| Componentes | Writer, Calc, Impress |
| Incidencias | Ninguna               |
| Técnico     | Nombre                |

Esta documentación permite posteriormente:

* Repetir la instalación.
* Auditar equipos.
* Resolver incidencias.
* Saber qué software está instalado.
* Planificar actualizaciones.

---

## 39. Incidencias durante la instalación

Una **incidencia** es un problema que aparece durante una operación o funcionamiento del sistema.

Ejemplos:

* Falta espacio.
* No existe compatibilidad.
* Falta un componente.
* El instalador se cierra.
* Aparece un error.
* El usuario no tiene permisos.
* La versión no corresponde con el sistema.
* Existe otra versión instalada.

---

## 40. Cómo documentar una incidencia

Una buena incidencia debería describir:

### 1. Problema

¿Qué ocurre?

### 2. Contexto

¿En qué equipo?

¿Con qué aplicación?

¿Con qué versión?

### 3. Mensaje de error

¿Qué indica exactamente el programa?

### 4. Diagnóstico

¿Qué hemos comprobado?

### 5. Solución

¿Qué hemos hecho?

### 6. Resultado

¿Se ha solucionado?

---

### Ejemplo

**Incidencia:**

> No se puede instalar la aplicación porque el sistema indica que no existe suficiente espacio disponible.

**Equipo:**

> PC-AULA-12.

**Diagnóstico:**

> El disco dispone de 1,2 GB libres y el instalador requiere 4 GB.

**Solución:**

> Se han eliminado archivos temporales y se ha liberado espacio.

**Resultado:**

> Se dispone de 8 GB libres y la instalación finaliza correctamente.

---

## 41. Resolución de problemas

Cuando una instalación falla debemos evitar actuar al azar.

Un procedimiento lógico sería:

```text
¿Existe un error?
       ↓
Leer mensaje
       ↓
Identificar causa probable
       ↓
Comprobar requisitos
       ↓
Comprobar permisos
       ↓
Comprobar espacio
       ↓
Comprobar compatibilidad
       ↓
Aplicar solución
       ↓
Volver a probar
       ↓
Documentar
```

Este método es mucho más profesional que simplemente volver a ejecutar el instalador repetidamente.

---

## 42. Desinstalación

En ocasiones no necesitamos instalar una aplicación, sino eliminarla.

La desinstalación correcta debe realizarse utilizando los mecanismos proporcionados por el sistema operativo o por la propia aplicación.

No debemos asumir que borrar la carpeta del programa equivale a desinstalarlo.

Una desinstalación puede implicar:

* Eliminación de archivos.
* Eliminación de configuraciones.
* Eliminación de accesos directos.
* Eliminación de componentes.
* Actualización del registro de aplicaciones instaladas.

---

## 43. Añadir y eliminar componentes

Algunas suites permiten modificar una instalación existente.

Por ejemplo:

```text
Instalación inicial

Writer       ✓
Calc         ✓
Impress      ✓
Base         ✓
Draw         ✓
```

Posteriormente el usuario puede decidir que Base no es necesario:

```text
Writer       ✓
Calc         ✓
Impress      ✓
Base         ✗
Draw         ✓
```

Esto permite adaptar la instalación a las necesidades reales.

---

## 44. Licencias y responsabilidad profesional

El técnico informático debe prestar especial atención a las licencias.

No es correcto instalar software comercial en múltiples equipos si la licencia adquirida solamente permite utilizarlo en uno.

Tampoco debemos utilizar software sin autorización simplemente porque técnicamente sea posible instalarlo.

En un entorno profesional debemos comprobar:

* Número de licencias.
* Número de usuarios.
* Número de equipos.
* Duración.
* Restricciones.
* Uso comercial.
* Condiciones de transferencia.

---

## 45. El concepto de software "gratis"

Supongamos que encontramos:

> "Descarga gratuita."

Esto no nos dice suficiente.

Podría tratarse de:

* Software libre.
* Freeware.
* Versión de prueba.
* Versión limitada.
* Software financiado mediante publicidad.
* Servicio gratuito con funciones adicionales de pago.

Por tanto:

> **Gratis describe el coste para el usuario; no necesariamente describe los derechos que tiene sobre el software.**

## 47. Entornos de explotación

El concepto de **entorno de explotación** hace referencia al conjunto de condiciones reales en las que funcionará una aplicación.

No debemos instalar una aplicación pensando únicamente en un ordenador aislado.

Debemos considerar el entorno completo:

```text
                 ENTORNO
                    │
       ┌────────────┼────────────┐
       │            │            │
   Hardware     Software      Usuarios
       │            │            │
       └────────────┼────────────┘
                    │
                Aplicación
                    │
             Datos / archivos
```

También podemos tener en cuenta:

* Red.
* Servidores.
* Seguridad.
* Políticas de la organización.
* Licencias.
* Copias de seguridad.
* Necesidades futuras.

## 48. Aplicaciones portables

Algunas aplicaciones pueden funcionar sin realizar una instalación convencional.

Son las denominadas **aplicaciones portables**.

Normalmente pueden ejecutarse desde:

* Carpeta local.
* Memoria USB.
* Disco externo.

Esto puede resultar útil en determinadas situaciones, pero no significa que sean siempre la mejor opción.

También debemos comprobar:

* Seguridad.
* Procedencia.
* Compatibilidad.
* Licencia.
* Actualizaciones.

## 49. Aplicaciones y seguridad

Las aplicaciones ofimáticas pueden trabajar con información muy importante.

Por ejemplo:

* Datos personales.
* Información económica.
* Contratos.
* Datos de clientes.
* Documentos internos.

Por eso debemos tener en cuenta la seguridad.

Algunas buenas prácticas son:

* Mantener las aplicaciones actualizadas.
* Utilizar software legítimo.
* Evitar fuentes desconocidas.
* Utilizar contraseñas adecuadas.
* Proteger los documentos.
* Realizar copias de seguridad.
* Controlar los permisos.
* No instalar software innecesario.

---

## 50. La importancia de las actualizaciones de seguridad

Una vulnerabilidad puede permitir que un atacante aproveche un problema existente en una aplicación.

Cuando el fabricante publica una actualización de seguridad, una de las finalidades puede ser corregir ese problema.

Por ello, mantener software desactualizado durante largos periodos puede aumentar el riesgo.

Sin embargo, en entornos profesionales tampoco debemos actualizar indiscriminadamente sin comprobar previamente la compatibilidad.

La estrategia correcta es:

> **Actualizar de forma planificada y controlada.**

---

## 51. Instalación, configuración y mantenimiento

Estas tres tareas están relacionadas pero no son exactamente iguales.

### Instalación

Hace que el software quede disponible en el sistema.

### Configuración

Adapta el funcionamiento del software a las necesidades del usuario.

### Mantenimiento

Incluye acciones posteriores como:

* Actualizaciones.
* Reparaciones.
* Cambios de configuración.
* Eliminación de componentes.
* Resolución de incidencias.

Podemos verlo así:

```text
             INSTALACIÓN
                  ↓
             CONFIGURACIÓN
                  ↓
               PRUEBAS
                  ↓
              UTILIZACIÓN
                  ↓
             MANTENIMIENTO
              ↙         ↘
      ACTUALIZACIÓN   INCIDENCIAS
```

---

## 52. El papel del técnico de sistemas

En un entorno profesional, el técnico no es simplemente la persona que "instala programas".

Su trabajo consiste en proporcionar soluciones adecuadas.

Debe ser capaz de:

1. Analizar las necesidades.
2. Identificar aplicaciones.
3. Comprobar requisitos.
4. Evaluar licencias.
5. Instalar software.
6. Configurarlo.
7. Realizar pruebas.
8. Actualizarlo.
9. Resolver incidencias.
10. Documentar las operaciones.

Por eso el conocimiento técnico debe combinarse con capacidad de análisis.

## 53. Resumen del tema

En este tema hemos aprendido que:

* La **ofimática** comprende herramientas destinadas a facilitar tareas de gestión de información.
* Existen diferentes tipos de aplicaciones ofimáticas.
* Una **suite ofimática** agrupa varias aplicaciones.
* Las aplicaciones pueden funcionar localmente o mediante servicios en la nube.
* Antes de instalar una aplicación debemos comprobar sus requisitos.
* Debemos comprobar la compatibilidad con el sistema.
* Las licencias determinan cómo podemos utilizar el software.
* Software gratuito y software libre no son conceptos equivalentes.
* Una instalación profesional debe seguir un procedimiento.
* Podemos instalar todos o solamente algunos componentes.
* Después de instalar una aplicación debemos configurarla y probarla.
* Las aplicaciones deben mantenerse actualizadas.
* Las actualizaciones pueden corregir errores, mejorar funcionalidades o solucionar problemas de seguridad.
* Las incidencias deben documentarse.
* Un técnico debe analizar las necesidades del entorno antes de elegir una solución.
