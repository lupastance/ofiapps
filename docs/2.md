# Instalación, configuración y mantenimiento de aplicaciones ofimáticas

## 1. Introducción

En el tema anterior aprendimos qué es la ofimática, qué tipos de aplicaciones existen y para qué se utilizan en una empresa.

Ahora vamos a dar un paso más: aprenderemos a **instalar, configurar, actualizar, mantener y desinstalar aplicaciones ofimáticas**.

Imaginemos que una empresa contrata a un técnico de sistemas porque necesita preparar diez ordenadores nuevos. Los trabajadores tienen que poder redactar documentos, elaborar hojas de cálculo, crear presentaciones y gestionar archivos PDF.

El técnico deberá decidir qué aplicaciones instalar, comprobar que los equipos cumplen los requisitos, seleccionar los instaladores adecuados, realizar la instalación, configurar el software y verificar que todo funciona correctamente.

Además, tendrá que mantener las aplicaciones actualizadas y resolver los problemas que puedan aparecer durante su utilización.

Estas tareas forman parte del trabajo habitual de un técnico de sistemas microinformáticos.

### Objetivos del tema

Al finalizar este tema, deberás ser capaz de:

- Identificar los requisitos de instalación de una aplicación.
- Comprobar la compatibilidad del software con el equipo.
- Diferenciar los principales tipos de instaladores.
- Identificar las condiciones de uso de una licencia de software.
- Preparar un ordenador antes de instalar una aplicación.
- Instalar aplicaciones ofimáticas en Windows y GNU/Linux.
- Reconocer las particularidades de las aplicaciones web.
- Realizar una configuración inicial.
- Buscar e instalar actualizaciones.
- Desinstalar aplicaciones correctamente.
- Diagnosticar errores frecuentes durante la instalación.
- Aplicar medidas básicas de seguridad.
- Documentar las aplicaciones instaladas en un equipo.

## 2. ¿Qué significa instalar una aplicación?

La **instalación de software** es el conjunto de operaciones necesarias para preparar una aplicación informática para su utilización en un sistema.

![](assets/apps.png){align="right"}

Según el programa, el proceso puede incluir:

- Copiar archivos al ordenador.
- Crear directorios.
- Instalar bibliotecas y componentes.
- Registrar información en el sistema operativo.
- Crear accesos directos.
- Asociar extensiones de archivo con una aplicación.
- Configurar permisos.
- Crear entradas en los menús de aplicaciones.
- Registrar servicios o tareas auxiliares.
- Configurar preferencias iniciales.


No todas las aplicaciones necesitan realizar todas estas operaciones.

Por ejemplo, algunas aplicaciones portátiles pueden ejecutarse directamente desde una carpeta sin un instalador tradicional.

### 2.1. Ejemplo práctico

Queremos instalar LibreOffice en un ordenador con Windows.

El procedimiento general sería:

1. Comprobar qué versión de Windows utiliza el equipo.
2. Verificar que el ordenador cumple los requisitos.
3. Descargar el instalador desde una fuente oficial.
4. Ejecutar el instalador.
5. Seleccionar las opciones de instalación.
6. Esperar a que finalice el proceso.
7. Abrir LibreOffice.
8. Crear un documento de prueba.
9. Guardar el documento y comprobar que puede volver a abrirse.

La instalación no termina simplemente cuando desaparece la ventana del instalador. También debemos comprobar que la aplicación funciona correctamente.

### 2.2. Instalación, configuración, actualización y mantenimiento

Son conceptos relacionados, pero no significan lo mismo.

| Operación | Descripción | Ejemplo |
|---|---|---|
| Instalación | Preparar el software para utilizarlo | Instalar LibreOffice |
| Configuración | Adaptar la aplicación a las necesidades del usuario | Cambiar el idioma de la interfaz |
| Actualización | Instalar una versión o revisión más reciente | Aplicar una actualización de seguridad |
| Mantenimiento | Realizar tareas para conservar el funcionamiento adecuado | Comprobar versiones y corregir errores |
| Reparación | Restaurar componentes dañados cuando la aplicación lo permite | Reparar una instalación de Office |
| Desinstalación | Eliminar la aplicación del sistema | Desinstalar una suite que ya no se utiliza |

**Importante:** actualizar una aplicación no siempre equivale a instalar una versión completamente nueva. Una actualización puede corregir errores, solucionar vulnerabilidades o incorporar nuevas funciones.

## 3. Requisitos de instalación de una aplicación

![](assets/requisitos.png){align="right"}

Antes de instalar un programa debemos comprobar que el equipo puede ejecutarlo correctamente.

Los requisitos de instalación describen las condiciones que debe cumplir el sistema para utilizar el software.

Podemos distinguir entre requisitos de hardware, requisitos de software y requisitos adicionales.

### 3.1. Requisitos de hardware

El hardware es la parte física del ordenador.

Los requisitos de hardware pueden incluir:

| Elemento | Qué debemos comprobar |
|---|---|
| Procesador | Arquitectura compatible y capacidad suficiente |
| Memoria RAM | Cantidad de memoria disponible |
| Almacenamiento | Espacio libre en disco |
| Tarjeta gráfica | Capacidades necesarias para determinadas aplicaciones |
| Pantalla | Resolución mínima recomendada |
| Conexión de red | Necesaria para descargar, activar o utilizar determinados servicios |

Por ejemplo, una aplicación que trabaja con documentos de texto sencillos puede funcionar correctamente en un equipo modesto, mientras que una herramienta de edición de vídeo puede necesitar bastante más memoria y capacidad de procesamiento.

No debemos confundir los requisitos mínimos con los recomendados.

- **Requisitos mínimos:** permiten ejecutar el programa en unas condiciones básicas.
- **Requisitos recomendados:** describen una configuración más adecuada para trabajar con comodidad.

Un equipo que cumple los requisitos mínimos puede funcionar, pero quizá ofrezca un rendimiento insuficiente para documentos grandes o tareas exigentes.

### 3.2. Requisitos de software

También debemos comprobar qué programas y componentes necesita la aplicación.

Por ejemplo:

- Una versión concreta de Windows.
- Una distribución y versión de GNU/Linux compatibles.
- Una arquitectura determinada.
- Bibliotecas del sistema.
- Un navegador actualizado.
- Un entorno de ejecución.
- Controladores específicos.
- Otros componentes de software.

Algunas aplicaciones pueden instalar automáticamente los componentes necesarios. Otras requieren que el administrador los prepare previamente.

### 3.3. Requisitos adicionales

Además de los requisitos técnicos, puede ser necesario disponer de:

- Una cuenta de usuario.
- Una conexión a Internet.
- Una licencia válida.
- Permisos de administrador.
- Credenciales corporativas.
- Espacio en un servicio de almacenamiento.
- Acceso a un servidor de licencias.

Por ejemplo, una aplicación puede instalarse correctamente, pero no permitir su utilización completa hasta que el usuario inicie sesión o active la licencia.

### 3.4. Cómo comprobar las características del equipo

![](assets/pc-requisitos.png){align="right"}

Antes de instalar software, el técnico debe conocer el sistema en el que va a trabajar.

#### En Windows

Podemos consultar la información del sistema desde la configuración de Windows o ejecutar:

```text
msinfo32
```

Este comando abre la herramienta Información del sistema.

También podemos abrir una terminal y ejecutar:

```powershell
systeminfo
```

Este comando muestra información sobre el sistema operativo, el procesador, la memoria y otros componentes.

Para comprobar la arquitectura de Windows, podemos consultar la sección de tipo de sistema en la configuración del equipo.

#### En GNU/Linux

Podemos utilizar los siguientes comandos:

```bash
uname -m
```

Muestra la arquitectura que está utilizando el sistema.

Por ejemplo:

- `x86_64`: arquitectura x86 de 64 bits.
- `aarch64`: arquitectura ARM de 64 bits.
- `i686`: arquitectura x86 de 32 bits.

Para consultar información del sistema operativo:

```bash
cat /etc/os-release
```

Para consultar la memoria:

```bash
free -h
```

Para consultar el espacio disponible:

```bash
df -h
```

Estos comandos permiten recopilar información antes de decidir si una aplicación es adecuada para el equipo.

## 4. Arquitectura y compatibilidad del software

![](assets/arquitectura.png){align="right"}

Uno de los aspectos más importantes de una instalación es la compatibilidad.

Una aplicación puede estar diseñada para funcionar únicamente en determinados sistemas operativos o arquitecturas.

### 4.1. Sistemas operativos

No todos los programas funcionan en todos los sistemas operativos.

Por ejemplo, una aplicación desarrollada exclusivamente para Windows no tiene por qué funcionar de forma nativa en GNU/Linux.

Antes de descargar un instalador debemos comprobar si está disponible para nuestro sistema.

Entre los sistemas operativos más habituales encontramos:

- Microsoft Windows.
- GNU/Linux.
- macOS.
- Android.
- iOS.

Algunas aplicaciones disponen de versiones para varios sistemas operativos. Otras solo se ofrecen para determinadas plataformas.

### 4.2. Arquitecturas de 32 y 64 bits

La arquitectura determina, entre otras cosas, cómo procesa el sistema las instrucciones y cómo gestiona la memoria.

Históricamente se han utilizado aplicaciones de 32 bits y de 64 bits.

En términos generales, una aplicación de 64 bits necesita un sistema operativo compatible con esa arquitectura. En cambio, algunos sistemas de 64 bits pueden ejecutar aplicaciones de 32 bits si disponen de los componentes de compatibilidad necesarios.

Por tanto, no debemos asumir que cualquier instalador funcionará en cualquier ordenador.

### 4.3. Ejemplo

Tenemos tres ordenadores:

| Equipo | Sistema | Arquitectura |
|---|---|---|
| A | Windows | 64 bits |
| B | GNU/Linux | ARM de 64 bits |
| C | Windows antiguo | 32 bits |

Si descargamos una aplicación disponible únicamente para Windows x86 de 64 bits:

- El equipo A podría ser compatible, si cumple los demás requisitos.
- El equipo B no podría ejecutarla de forma nativa por utilizar otra plataforma y arquitectura.
- El equipo C no podría ejecutar directamente esa versión de 64 bits.

En todos los casos habría que comprobar también los requisitos específicos del programa.

### 4.4. Compatibilidad de archivos

La compatibilidad también importa después de instalar la aplicación.

Por ejemplo, LibreOffice Writer y Microsoft Word pueden trabajar con documentos `.docx`, aunque algunos elementos complejos pueden visualizarse de forma diferente.

Por ello debemos distinguir entre:

- Compatibilidad del programa con el sistema operativo.
- Compatibilidad del programa con otros componentes.
- Compatibilidad de los archivos con otras aplicaciones.

## 5. Tipos de instaladores y métodos de distribución

El software puede distribuirse mediante diferentes formatos y mecanismos.

Conocerlos nos ayuda a identificar cómo instalar una aplicación y qué procedimiento debemos seguir.

### 5.1. Instaladores ejecutables

![](assets/batch.png){align="right"}

En Windows es habitual encontrar instaladores con extensiones como:

- `.exe`
- `.msi`

Un archivo `.exe` puede ser un instalador, pero también puede ser otro tipo de programa ejecutable. La extensión por sí sola no garantiza que el archivo sea seguro.

Un archivo `.msi` utiliza Windows Installer, una tecnología de instalación de Windows.

Los instaladores pueden ofrecer asistentes gráficos con opciones como:

- Elegir la carpeta de instalación.
- Seleccionar componentes.
- Crear accesos directos.
- Aceptar una licencia.
- Instalar para un usuario o para todo el equipo.

### 5.2. Paquetes de GNU/Linux

![](assets/linux.png){class="center"}

En GNU/Linux, muchas aplicaciones se distribuyen mediante paquetes gestionados por el sistema.

En Debian y sus derivados, como Ubuntu y Raspberry Pi OS, es habitual utilizar paquetes `.deb`.

En distribuciones basadas en RPM se pueden encontrar paquetes `.rpm`.

Sin embargo, en lugar de descargar e instalar paquetes manualmente, normalmente es preferible utilizar los repositorios y el gestor de paquetes de la distribución.

Esto permite resolver dependencias y recibir actualizaciones a través de los mecanismos habituales del sistema.

### 5.3. Instalación mediante repositorios

Un repositorio es una fuente organizada de paquetes de software.

El sistema consulta los repositorios configurados para localizar, descargar e instalar aplicaciones.

En Debian podemos utilizar `apt`.

Por ejemplo:

```bash
sudo apt update
sudo apt install libreoffice
```

El primer comando actualiza la información local sobre los paquetes disponibles.

El segundo solicita la instalación de LibreOffice y de las dependencias necesarias.

**Importante:** `apt update` no actualiza por sí mismo todos los programas instalados. Actualiza la información de los repositorios.

### 5.4. Tiendas de aplicaciones

Algunos sistemas operativos ofrecen tiendas o catálogos gráficos.

Desde ellas podemos:

- Buscar aplicaciones.
- Consultar descripciones.
- Verificar el editor.
- Instalar programas.
- Actualizar aplicaciones.
- Desinstalar determinados paquetes.

Las tiendas pueden simplificar el proceso de instalación, aunque siempre debemos comprobar la procedencia del software y los permisos que necesita.

### 5.5. Aplicaciones portátiles

Una aplicación portátil puede ejecutarse sin pasar por una instalación tradicional.

En algunos casos basta con extraer un archivo comprimido y ejecutar el programa.

Sus ventajas pueden ser:

- No necesitar un asistente de instalación.
- Poder utilizarse desde una carpeta específica.
- Facilitar ciertas tareas de mantenimiento.

Sin embargo, el término *portátil* no significa automáticamente que una aplicación sea segura o que funcione en todos los equipos.

También puede necesitar permisos, componentes adicionales o una arquitectura compatible.

### 5.6. Formatos universales en GNU/Linux

Además de los paquetes tradicionales, existen formatos de distribución que intentan facilitar el uso de aplicaciones en distintas distribuciones.

Algunos ejemplos son:

- Flatpak.
- Snap.
- AppImage.

Cada formato tiene características diferentes.

Flatpak y Snap utilizan mecanismos propios para distribuir aplicaciones y gestionar dependencias. AppImage permite distribuir muchas aplicaciones como archivos ejecutables independientes.

La disponibilidad y el procedimiento de instalación dependen del sistema y de la aplicación.

### 5.7. Aplicaciones web

Una aplicación web se utiliza habitualmente desde un navegador.

En este caso, el usuario puede no necesitar instalar un programa tradicional en su ordenador.

Por ejemplo, puede utilizar un procesador de textos online para crear documentos desde un navegador.

No obstante, el navegador y el sistema operativo siguen necesitando mantenimiento y actualizaciones.

### Comparativa de métodos de instalación

| Método | Ejemplo | Característica |
|---|---|---|
| Instalador ejecutable | `.exe` | Habitual en Windows |
| Windows Installer | `.msi` | Utiliza Windows Installer |
| Paquete Debian | `.deb` | Utilizado en Debian y derivados |
| Gestor de paquetes | `apt` | Gestiona paquetes y dependencias |
| Tienda de aplicaciones | Catálogo gráfico | Simplifica la instalación |
| Aplicación portátil | Programa ejecutable desde una carpeta | Puede evitar la instalación tradicional |
| Flatpak / Snap | Paquetes de aplicaciones | Sistemas de distribución específicos |
| Aplicación web | Procesador de textos online | Se utiliza normalmente desde un navegador |

## 6. Licencias y condiciones de uso

Antes de instalar una aplicación debemos conocer las condiciones bajo las que podemos utilizarla.

Una licencia de software establece los derechos y restricciones aplicables al programa.

No debemos confundir la posibilidad técnica de instalar una aplicación con el derecho legal a utilizarla en cualquier circunstancia.

### 6.1. Software propietario

El software propietario está sujeto a las condiciones establecidas por su titular.

La licencia puede limitar aspectos como:

- El número de dispositivos.
- El uso comercial.
- La copia o redistribución.
- La modificación del programa.
- El acceso al código fuente.

Por ejemplo, determinadas ediciones comerciales de una suite ofimática requieren una licencia o suscripción válida.

### 6.2. Software libre y de código abierto

El software libre respeta determinadas libertades de los usuarios, como ejecutar el programa, estudiar su funcionamiento, modificarlo y redistribuir copias conforme a la licencia correspondiente.

El software de código abierto permite acceder al código fuente bajo unas condiciones de licencia específicas.

Ambos conceptos están relacionados, pero no deben tratarse como etiquetas que garanticen por sí solas cualquier derecho: siempre hay que consultar la licencia concreta.

**Software libre no significa necesariamente software gratuito.** Puede venderse y también puede ofrecerse sin coste.

### 6.3. Software gratuito

Una aplicación gratuita no tiene coste económico para el usuario en las condiciones de uso ofrecidas.

Sin embargo, podría ser propietaria y no permitir modificaciones ni redistribución.

Por ejemplo, una aplicación puede ofrecer una versión gratuita para uso personal y exigir una licencia comercial para una empresa.

### 6.4. Licencias comerciales y educativas

En el entorno educativo pueden existir licencias específicas para centros, docentes y estudiantes.

Antes de instalar una aplicación en un aula debemos comprobar:

- Si la licencia permite el uso educativo.
- Si permite instalarla en todos los equipos necesarios.
- Si es válida para uso comercial o exclusivamente educativo.
- Si exige crear cuentas.
- Si tiene fecha de caducidad.
- Si se requiere activación individual.

No debemos asumir que una aplicación puede instalarse gratuitamente en todos los ordenadores de una empresa o un centro educativo por el simple hecho de disponer de una versión gratuita.

## 7. Preparación del equipo antes de instalar

Una instalación correcta empieza antes de ejecutar el instalador.

El técnico debe preparar el equipo para reducir el riesgo de errores y evitar interrupciones.

### 7.1. Comprobar los requisitos

Debemos verificar:

- Sistema operativo.
- Arquitectura.
- Memoria.
- Espacio disponible.
- Dependencias.
- Conexión a Internet, si es necesaria.
- Licencia.
- Permisos de instalación.

### 7.2. Comprobar el espacio disponible

El instalador puede necesitar más espacio temporal del que ocupará finalmente la aplicación.

Por ejemplo, durante una instalación puede ser necesario descargar un archivo, extraerlo y copiar los componentes al disco.

En Windows podemos comprobar el espacio disponible desde el Explorador de archivos.

En GNU/Linux podemos utilizar:

```bash
df -h
```

### 7.3. Comprobar los permisos

Algunas instalaciones requieren privilegios de administrador porque modifican componentes compartidos del sistema.

En Windows puede aparecer una solicitud de confirmación del Control de cuentas de usuario.

En GNU/Linux, determinadas operaciones administrativas se realizan con `sudo`.

No debemos conceder permisos elevados a programas de procedencia desconocida.

### 7.4. Descargar desde una fuente fiable

Debemos obtener las aplicaciones de fuentes confiables, preferiblemente:

- La web oficial del desarrollador.
- Los repositorios oficiales de la distribución.
- La tienda de aplicaciones del sistema.
- El portal corporativo autorizado.

Evita las páginas que ofrecen instaladores modificados, descargadores de terceros o programas adicionales que no has solicitado.

Cuando el desarrollador proporciona una suma de comprobación o firma digital, podemos utilizarla para verificar la integridad o procedencia del archivo según el mecanismo indicado.

### 7.5. Cerrar documentos y aplicaciones

Antes de instalar o actualizar una aplicación conviene guardar el trabajo y cerrar los documentos que estén abiertos con ella.

Algunas instalaciones necesitan sustituir archivos que están en uso o reiniciar componentes.

### 7.6. Crear una copia de seguridad cuando proceda

En una instalación habitual de una aplicación nueva puede no ser necesario realizar una copia completa del sistema.

Sin embargo, antes de actualizar una aplicación crítica o realizar cambios importantes debemos valorar la necesidad de respaldar:

- Documentos.
- Plantillas.
- Diccionarios personalizados.
- Macros.
- Configuraciones.
- Complementos.
- Perfiles de usuario.

La configuración y los datos personales no siempre se conservan al desinstalar una aplicación.

### Lista de comprobación previa

| Comprobación | Hecho |
|---|---|
| El sistema operativo es compatible | ☐ |
| La arquitectura es compatible | ☐ |
| Hay espacio suficiente | ☐ |
| Se dispone de los permisos necesarios | ☐ |
| La fuente de descarga es fiable | ☐ |
| Se ha comprobado la licencia | ☐ |
| Los documentos importantes están guardados | ☐ |
| Se ha valorado si es necesaria una copia de seguridad | ☐ |

## 8. Instalación de aplicaciones en Windows

![](assets/windows.png){class="center"}

Vamos a utilizar LibreOffice como ejemplo porque es una suite ofimática que permite trabajar con documentos, hojas de cálculo y presentaciones.

Los nombres exactos de algunas opciones pueden cambiar entre versiones del instalador.

### 8.1. Paso 1: comprobar el sistema

Antes de descargar el programa debemos conocer la versión de Windows y la arquitectura del equipo.

Podemos abrir la configuración y consultar la información del sistema.

También podemos ejecutar:

```text
msinfo32
```

Debemos asegurarnos de que el instalador elegido es compatible con el sistema.

### 8.2. Paso 2: descargar el instalador

Accedemos a la web oficial:

https://www.libreoffice.org/download/

Seleccionamos la versión apropiada para nuestro sistema operativo.

Antes de ejecutar el archivo, debemos comprobar que procede de la fuente esperada y que no se trata de un descargador de terceros.

!!!tip
    También podemos hacerlo a través de la consola usando el comando ***winget***

    ```bash
        winget search LibreOffice
    ```

### 8.3. Paso 3: iniciar el instalador

Ejecutamos el archivo descargado.

Dependiendo de la configuración del equipo, Windows puede solicitar autorización para permitir que el instalador realice cambios.

Debemos comprobar el nombre del programa antes de aceptar.

### 8.4. Paso 4: seguir el asistente

El instalador puede permitirnos elegir:

- Instalación típica o personalizada.
- Componentes.
- Carpeta de destino.
- Accesos directos.
- Asociaciones de archivos.

En un equipo de uso general, la instalación típica suele ser suficiente.

En un entorno profesional, una instalación personalizada puede ser útil cuando necesitamos controlar exactamente qué componentes se instalan.

### 8.5. Paso 5: finalizar la instalación

Cuando termine el proceso, cerramos el asistente y comprobamos que LibreOffice aparece en el menú de aplicaciones.

### 8.6. Paso 6: verificar el funcionamiento

Abrimos Writer y realizamos una prueba:

1. Creamos un documento.
2. Escribimos un texto.
3. Guardamos el archivo en formato `.odt`.
4. Cerramos el documento.
5. Volvemos a abrirlo.
6. Comprobamos que el contenido se conserva.

Podemos repetir el proceso guardando una copia en formato `.docx` para comprobar la compatibilidad con otros programas.

**Una instalación debe verificarse, no darse por correcta únicamente porque el asistente haya terminado.**

### 8.7. Instalación mediante Windows Package Manager

Windows dispone de un gestor de paquetes denominado `winget` en los sistemas compatibles.

Este permite instalar aplicaciones desde la línea de comandos sin tener que buscar y ejecutar manualmente cada instalador.

En una terminal podemos consultar si está disponible:

```powershell
winget --version
```

Si está instalado, podemos buscar LibreOffice:

```powershell
winget search LibreOffice
```

Y solicitar su instalación utilizando el identificador que muestre el catálogo:

```powershell
winget install --id TheDocumentFoundation.LibreOffice -e
```

El identificador debe comprobarse en el catálogo antes de ejecutar el comando, ya que los identificadores y las fuentes pueden cambiar.

Este método es especialmente interesante para un técnico que debe preparar varios equipos.

### Actividad 4. Instala y verifica

## 9. Instalación de aplicaciones en GNU/Linux

![](assets/paquetes.png){align="right"}

En GNU/Linux es habitual utilizar un gestor de paquetes para instalar y mantener las aplicaciones.

Trabajaremos con Debian y sus derivados, aunque el procedimiento puede variar en otras distribuciones.

### 9.1. ¿Qué es un gestor de paquetes?

Un gestor de paquetes es una herramienta que permite instalar, actualizar, configurar y eliminar paquetes de software.

Entre sus funciones se encuentran:

- Localizar paquetes disponibles.
- Descargar los archivos necesarios.
- Resolver dependencias.
- Instalar componentes.
- Registrar los paquetes instalados.
- Eliminar paquetes.
- Facilitar las actualizaciones.

En Debian se utiliza habitualmente `apt`.

### 9.2. Actualizar la información de los repositorios

Antes de instalar una aplicación podemos ejecutar:

```bash
sudo apt update
```

El sistema consulta las fuentes configuradas y actualiza la información sobre los paquetes disponibles.

Este comando no significa que todas las aplicaciones estén ya actualizadas.

### 9.3. Instalar LibreOffice

Podemos solicitar la instalación de la suite mediante:

```bash
sudo apt install libreoffice
```

El gestor de paquetes mostrará los paquetes que necesita instalar y podrá pedir confirmación.

Una vez aceptada la operación, descargará e instalará los componentes necesarios.

### 9.4. Comprobar que está instalada

Podemos consultar la versión:

```bash
libreoffice --version
```

También podemos abrir la aplicación desde el menú del entorno gráfico.

Si estamos utilizando un sistema sin escritorio gráfico, la disponibilidad y el funcionamiento de las aplicaciones gráficas dependerán de los componentes instalados y del entorno de ejecución.

### 9.5. Buscar paquetes

Podemos buscar aplicaciones relacionadas con una palabra:

```bash
apt search libreoffice
```

Este comando muestra paquetes disponibles relacionados con la búsqueda.

Para consultar paquetes instalados:

```bash
dpkg -l | grep libreoffice
```

La salida dependerá de los componentes que estén instalados en el equipo.

### 9.6. Eliminar una aplicación

Para eliminar el paquete principal podemos utilizar:

```bash
sudo apt remove libreoffice
```

El gestor de paquetes indicará qué paquetes se eliminarán.

No debemos utilizar comandos de eliminación sin leer antes la lista de cambios que propone el sistema.

Además, eliminar una aplicación no implica necesariamente borrar todas las preferencias y documentos del usuario.

### 9.7. ¿Por qué utilizar repositorios?

Los repositorios facilitan la instalación y el mantenimiento porque el sistema conoce los paquetes y sus dependencias.

También permiten recibir actualizaciones mediante el mecanismo habitual de la distribución.

Descargar paquetes manualmente puede ser necesario en determinados casos, pero exige prestar más atención a la procedencia, compatibilidad y mantenimiento del software.

### Actividad 5. Instala desde la terminal

## 11. Configuración inicial de una aplicación

Después de instalar una aplicación debemos adaptarla a las necesidades del usuario.

La **configuración** consiste en modificar las opciones del programa para que funcione de la forma deseada.

La configuración puede afectar al idioma, los documentos, las rutas, la interfaz y otros aspectos.

### 11.1. Idioma

Una aplicación puede permitir configurar:

- Idioma predeterminado de los documentos.
- Corrector ortográfico.

### 11.2. Carpetas y rutas

Muchas aplicaciones permiten configurar dónde se guardan determinados archivos.

Por ejemplo:

- Documentos.
- Plantillas.
- Copias de seguridad.
- Imágenes.
- Exportaciones.
- Archivos temporales.

Una empresa puede establecer carpetas compartidas para facilitar la organización, siempre respetando los permisos de acceso.

### 11.3. Formatos predeterminados

Algunas aplicaciones permiten elegir el formato que se utilizará al guardar nuevos documentos.

Por ejemplo, LibreOffice puede trabajar con formatos OpenDocument y también con formatos de Microsoft Office.

Es importante elegir el formato en función de las necesidades.

Si el documento se va a seguir editando con LibreOffice, OpenDocument puede ser una opción apropiada. Si debemos intercambiarlo con usuarios que utilizan Microsoft Office, puede resultar conveniente utilizar un formato compatible con esa suite.

Para distribuir una versión final que no necesite edición, podemos exportar el documento a PDF.

### 11.4. Asociaciones de archivos

| Extensión | Aplicación habitual |

| `.ods` | LibreOffice Calc |
| `.odp` | LibreOffice Impress |
| `.pdf` | Visor de PDF |
| `.docx` | Procesador de textos compatible |
| `.xlsx` | Hoja de cálculo compatible |

Estas asociaciones pueden variar según la configuración del equipo.

No todos los sistemas tienen que utilizar exactamente las mismas aplicaciones predeterminadas.

### 11.5. Complementos y extensiones

Algunas aplicaciones permiten añadir extensiones que incorporan funcionalidades adicionales.

Antes de instalar una extensión debemos comprobar:

- Quién la desarrolla.
- Si es compatible con nuestra versión.
- Qué permisos necesita.
- Si recibe mantenimiento.
- Si procede de una fuente fiable.

Un complemento puede ampliar las funciones del programa, pero también introducir riesgos si procede de una fuente desconocida.

### 11.6. Configuración del usuario y configuración del sistema

Algunas preferencias afectan solo a una cuenta de usuario, mientras que otras pueden aplicarse a todo el equipo.

Por ejemplo:

- Una preferencia personal puede ser el idioma de la interfaz.
- Una configuración del sistema puede establecer una ruta compartida o una política de seguridad.

En una empresa, el administrador debe decidir qué opciones puede modificar cada usuario.

## 12. Actualizaciones y mantenimiento

El software necesita mantenimiento para corregir errores, mejorar su funcionamiento y reducir los riesgos de seguridad.

Una aplicación que funcionaba correctamente hace meses puede contener vulnerabilidades conocidas o presentar problemas de compatibilidad con otros componentes.

### 12.1. Tipos de actualizaciones

Podemos distinguir entre:

| Tipo | Objetivo |
|---|---|
| Actualización de seguridad | Corregir vulnerabilidades |
| Corrección de errores | Solucionar fallos |
| Actualización funcional | Añadir o modificar características |
| Actualización de compatibilidad | Mejorar el funcionamiento con otros componentes |
| Actualización mayor | Incorporar cambios importantes en una nueva versión |

Estas categorías pueden solaparse. Una misma actualización puede corregir errores y añadir funcionalidades.

### 12.2. ¿Por qué debemos actualizar?

Las actualizaciones pueden:

- Corregir vulnerabilidades.
- Mejorar la estabilidad.
- Resolver problemas.
- Mejorar la compatibilidad.
- Añadir funciones.
- Corregir errores de interpretación de archivos.

No actualizar puede provocar problemas de seguridad y compatibilidad.

Sin embargo, en un entorno profesional no siempre conviene instalar cualquier actualización inmediatamente sin comprobar su impacto.

### 12.3. Actualizar en Windows

Las aplicaciones pueden actualizarse mediante distintos mecanismos:

- El actualizador integrado.
- La web oficial del desarrollador.
- El gestor de paquetes.
- La tienda de aplicaciones.
- Las herramientas de administración corporativa.

El método depende del programa.

Antes de actualizar una aplicación importante debemos comprobar si existen documentos abiertos, si se necesita reiniciar y si hay requisitos especiales.

### 12.4. Actualizar en Debian

En Debian podemos consultar e instalar actualizaciones de los paquetes disponibles en los repositorios configurados.

Primero actualizamos la información:

```bash
sudo apt update
```

Después podemos consultar qué paquetes tienen actualizaciones disponibles:

```bash
apt list --upgradable
```

Si queremos actualizar los paquetes instalados:

```bash
sudo apt upgrade
```

El sistema mostrará los cambios que va a realizar.

Debemos revisar las operaciones propuestas antes de confirmarlas, especialmente en equipos de producción.

**Importante:** estos comandos afectan al sistema y no solo a LibreOffice. En un ordenador administrado por el centro, deben ejecutarse únicamente con autorización.

### 12.5. Actualizaciones automáticas y manuales

Las actualizaciones pueden gestionarse de diferentes formas.

**Automáticas:**

El sistema o la aplicación descarga e instala determinadas actualizaciones sin intervención constante del usuario.

Ventaja: reducen el riesgo de mantener versiones antiguas.

Inconveniente: una actualización puede provocar cambios inesperados o incompatibilidades.

**Manuales:**

El administrador decide cuándo instalar las actualizaciones.

Ventaja: permite planificar pruebas y despliegues.

Inconveniente: requiere supervisión y puede retrasar la instalación de correcciones importantes.

En una empresa se puede utilizar una estrategia mixta: probar primero las actualizaciones y desplegarlas después de forma controlada.

### 12.6. Mantenimiento preventivo

El mantenimiento preventivo pretende reducir la probabilidad de que aparezcan problemas.

Algunas acciones son:

- Comprobar las versiones instaladas.
- Aplicar actualizaciones de seguridad.
- Revisar los requisitos.
- Comprobar las extensiones.
- Eliminar programas innecesarios.
- Verificar las copias de seguridad.
- Revisar las licencias.
- Comprobar la compatibilidad con los documentos de la empresa.

## 13. Desinstalación de aplicaciones

La desinstalación consiste en retirar una aplicación del sistema utilizando el procedimiento adecuado.

No es lo mismo desinstalar un programa que borrar manualmente su carpeta.

Una desinstalación correcta puede necesitar eliminar o registrar cambios en:

- Archivos del programa.
- Entradas del sistema.
- Accesos directos.
- Componentes compartidos.
- Asociaciones de archivos.
- Servicios.
- Componentes auxiliares.

No todas las aplicaciones utilizan los mismos mecanismos.

### 13.1. Desinstalar en Windows

En Windows podemos acudir a la configuración del sistema, entrar en la sección de aplicaciones instaladas y seleccionar el programa que queremos eliminar.

Después seguimos las instrucciones del desinstalador.

Al finalizar, podemos comprobar si la aplicación ha desaparecido de la lista y si se han eliminado sus accesos directos.

Algunos datos personales o configuraciones pueden conservarse. Esto depende de la aplicación y del procedimiento utilizado.

### 13.2. Desinstalar en Debian

Podemos utilizar:

```bash
sudo apt remove libreoffice
```

Antes de confirmar, debemos revisar qué paquetes se eliminarán.

Si deseamos consultar paquetes que ya no son necesarios como dependencias, podemos utilizar:

```bash
sudo apt autoremove
```

**Atención:** no debemos aceptar automáticamente cualquier operación de eliminación. Hay que leer la lista de paquetes propuesta para asegurarnos de que no se elimina software necesario.

### 13.3. ¿Qué ocurre con los documentos?

Desinstalar un procesador de textos no debería interpretarse como una orden para eliminar los documentos creados con él.

Los documentos del usuario suelen estar almacenados en carpetas independientes de la instalación del programa.

Aun así, antes de desinstalar software debemos identificar dónde se encuentran los archivos personales, plantillas y configuraciones que necesitamos conservar.

### 13.4. ¿Cuándo debemos desinstalar una aplicación?

Algunas razones habituales son:

- La aplicación ya no se utiliza.
- Ha sido sustituida por otra.
- Existe una versión incompatible.
- El programa está dañado y requiere una reinstalación.
- Se ha detectado software no autorizado.
- Es necesario liberar espacio.
- Ha terminado el periodo de uso permitido por una licencia.

La desinstalación debe responder a una necesidad concreta y no realizarse de forma indiscriminada.

## 14. Resolución de problemas durante la instalación

Los errores de instalación son habituales en el trabajo de un técnico.

Lo importante no es únicamente conocer posibles soluciones, sino seguir un método ordenado para identificar la causa.

### 14.1. Método general de diagnóstico

Podemos utilizar este procedimiento:

1. **Identificar el problema.** ¿Qué mensaje aparece?
2. **Recopilar información.** ¿Qué sistema y versión utiliza el equipo?
3. **Reproducir el error**, si es seguro y necesario.
4. **Formular una hipótesis.** ¿Qué puede estar fallando?
5. **Aplicar una solución controlada.**
6. **Comprobar el resultado.**
7. **Documentar la incidencia.**

No debemos empezar a cambiar configuraciones al azar. Cada modificación debe tener una razón y, cuando sea posible, debe poder revertirse.

### 14.2. Errores frecuentes

| Problema | Causas posibles | Qué comprobar |
|---|---|---|
| El instalador no se abre | Archivo dañado, formato incorrecto o bloqueo | Fuente, integridad y compatibilidad |
| Aparece un error de arquitectura | Instalador incompatible | Arquitectura del sistema y del programa |
| No hay espacio suficiente | Disco lleno | Espacio disponible y requisitos |
| Se deniega la instalación | Falta de permisos | Cuenta y autorización |
| Faltan componentes | Dependencias no disponibles | Requisitos y registros del instalador |
| La descarga falla | Problemas de conexión o servidor | Red y disponibilidad de la fuente |
| El programa no aparece en el menú | Instalación incompleta o acceso directo ausente | Estado de instalación y ubicación |
| La aplicación se cierra al abrirla | Incompatibilidad, configuración o archivos dañados | Requisitos, mensajes y registros |
| Los documentos se ven diferentes | Diferencias entre formatos o aplicaciones | Formato, fuentes y características utilizadas |
| No se puede actualizar | Permisos, archivos en uso o repositorios | Mensaje exacto y estado del sistema |

### 14.3. El instalador no se abre

Primero debemos comprobar:

- Si el archivo se ha descargado completamente.
- Si procede de una fuente fiable.
- Si corresponde al sistema operativo.
- Si necesita una herramienta específica para abrirse.
- Si existe algún mensaje de error.

No debemos desactivar las medidas de seguridad del sistema simplemente porque un instalador no se abra.

### 14.4. Falta espacio en disco

Podemos consultar el espacio disponible y comprobar si existen archivos temporales que puedan eliminarse de forma segura.

No debemos borrar carpetas del sistema sin conocer su función.

Antes de eliminar archivos conviene identificar qué ocupa espacio y comprobar si contiene información importante.

### 14.5. Falta de permisos

Algunas instalaciones requieren permisos administrativos.

Si el usuario no dispone de ellos, la solución puede ser solicitar la intervención del administrador.

No debemos intentar eludir las políticas del centro educativo o de la empresa.

### 14.6. Dependencias ausentes

Una aplicación puede necesitar bibliotecas o componentes adicionales.

Los gestores de paquetes suelen facilitar la instalación de dependencias compatibles.

Si una instalación falla, debemos revisar el mensaje de error y comprobar qué componente falta antes de instalar paquetes adicionales.

### 14.7. El programa funciona, pero no abre un archivo

En ese caso, el problema no tiene por qué estar en la instalación.

Debemos comprobar:

- La extensión del archivo.
- El formato real del contenido.
- La aplicación asociada.
- La compatibilidad del formato.
- Si el archivo está dañado.
- Si el documento necesita una versión más reciente.
- Si existen restricciones de acceso.

Un archivo puede tener una extensión incorrecta o estar dañado, por lo que cambiar la extensión manualmente no garantiza que funcione.

## 15. Seguridad durante la instalación

Instalar software implica introducir nuevos componentes en el sistema. Si el programa es malicioso o está modificado, puede poner en peligro los datos y la seguridad del equipo.

Por eso debemos aplicar buenas prácticas.

### 15.1. Descargar de fuentes fiables

Debemos preferir la web oficial del desarrollador o los repositorios autorizados.

No debemos confiar en un archivo únicamente porque su nombre coincida con el de una aplicación conocida.

### 15.2. Revisar los permisos

Los instaladores pueden solicitar permisos elevados para modificar el sistema.

Antes de concederlos, debemos comprobar qué programa los solicita y por qué.

### 15.3. Evitar software innecesario

Durante algunas instalaciones pueden ofrecerse componentes adicionales.

Debemos leer las opciones y no instalar programas que no necesitamos.

### 15.4. Mantener el sistema actualizado

Las actualizaciones pueden corregir vulnerabilidades tanto del sistema operativo como de las aplicaciones.

### 15.5. Utilizar cuentas con privilegios adecuados

Para tareas cotidianas es preferible utilizar una cuenta con permisos limitados cuando sea posible.

Los privilegios administrativos deben utilizarse cuando la tarea realmente los necesita.

### 15.6. Proteger los datos

Antes de realizar cambios importantes debemos valorar la necesidad de una copia de seguridad.

Además, no debemos compartir documentos confidenciales durante las pruebas ni utilizar datos personales reales si no son necesarios.

### 15.7. Desconfiar de los instaladores modificados

Debemos evitar programas pirateados, activadores desconocidos e instaladores modificados.

Además de los problemas legales, pueden incluir software malicioso o alterar el funcionamiento del equipo.

# 20. Resumen del tema

En este tema hemos aprendido que la instalación y el mantenimiento de aplicaciones ofimáticas son tareas importantes para un técnico de sistemas.

Las ideas fundamentales son:

- Antes de instalar software debemos comprobar sus requisitos y la compatibilidad del equipo.
- Los instaladores pueden adoptar distintos formatos según el sistema operativo.
- Los gestores de paquetes facilitan la instalación y el mantenimiento de las aplicaciones.
- La licencia determina las condiciones legales de uso.
- Una instalación debe realizarse desde una fuente fiable.
- La configuración inicial adapta la aplicación a las necesidades del usuario.
- Las actualizaciones pueden incorporar funciones y corregir errores o vulnerabilidades.
- La desinstalación debe realizarse mediante los mecanismos adecuados.
- Los errores deben diagnosticarse de forma ordenada.
- La seguridad debe tenerse en cuenta durante todo el proceso.
- El inventario y la documentación facilitan el mantenimiento de los equipos.
- Una instalación correcta debe verificarse mediante pruebas.
